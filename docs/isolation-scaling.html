KEDA Autoscaling & Git Branching Operators

Tharior Remedai leverages Kubernetes Custom Resource Definitions (CRDs) and specialized operators for dynamic pod scaling and Git branch lifecycle management.

1. KEDA Autoscaling Operator (`keda_operator.py`)

The KEDA Operator dynamically balances workloads across two tiers:

  • Shared Deployment Autoscaling (KEDA ScaledObject): Monitors queue backlog (Redis/Anvesh) and Prometheus active task counts to scale worker pods from 2 to 40 replicas.
  • Dynamic Ephemeral Pod Provisioning (KEDA ScaledJob): When a high-tier task (Tiers 8–10) or mission-critical security task is dispatched, the operator provisions a dedicated, single-tenant isolated pod with POSIX 0700 scratchpads and auto-terminates upon completion.

2. Git Branching Lifecycle Operator (`branch_operator.py`)

The Branch Operator enforces clean Git practices across all remediation pipelines:

Sanitized Branch Naming

Converts issue metadata into sanitized branch names conforming to standards: tharior/fix-{TICKET_ID}-{slug}.

Automated Trunk Rebase

Rebases remediation branches on the latest trunk HEAD prior to pull request generation to detect merge conflicts early.

Post-Merge Branch Pruning

Automatically prunes ephemeral branches from git repositories once pull requests are merged or closed.

3. Kubernetes Custom Resource Definitions (CRD)

Manifests located in deploy/k8s/:

  • deploy/k8s/crd-remediation-branch.yaml: CRD for RemediationBranch resource.
  • deploy/k8s/keda-scaledobject.yaml: ScaledObject definition for deployment scaling.
  • deploy/k8s/keda-scaledjob.yaml: ScaledJob definition for single-tenant ephemeral pods.
  • deploy/k8s/keda-operator-deployment.yaml: Complete KEDA v2.14 operator and metrics server deployment.
